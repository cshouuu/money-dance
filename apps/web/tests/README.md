# 弹窗滚动回归

启动 `npm run dev -w @salary-flow/web`，打开 `/tests/modal-scroll.html`。此页直接使用业务组件及线上 CSS 加载顺序，不读取、修改或清空用户数据，也不进入生产构建。

## 操作

1. 视口设为 360×560，打开 `attendance`，选择请假。向下滚动至「保存出勤」，再滚回标题。切换为计薪后重复检查。
2. 视口设为 360×320，逐一打开 attendance、confirm、early-finish、ledger、overtime-start、overtime-backfill、slacking、work-time。必须能够滚动至顶部与底部；最后的操作按钮不能被屏幕裁切。仅检查 CSS 的 `overflow` 值不足以确认通过，必须实际滚动。
3. 打开 `picker`，点击日期时间。拖动标题或滚轮两侧空白区域可以滚动整个弹窗，拖动某列只改变该列选择；「完成」应能显示并点击。分别检查日期、时间和日期时间入口。
4. 打开 `sheet`，标题包含多行说明。滚动内容至「底部操作」，确认按钮完整显示；拖动顶部手柄仍能关闭。
5. 打开 `select`，滚动至「选项 30」并选择。检查弹窗中的请假类型下拉列表也能选择末项。
6. 在 740×320 横屏和 1280×800 桌面视口检查弹窗边界与操作。关闭弹窗后，背景页面应恢复滚动。

## 2026-09-06 验证记录

- 修复前，360×560 的出勤弹窗内容高 679px，可视高 526px；实际滚动后 scrollTop 仍为 0（纵向 overflow 为 hidden）。修复后可滚到 153px，保存按钮完整显示。
- 360×320 实际向上、向下滚动：8 类业务弹窗均到达 scrollTop=0 和最大滚动距离；底部操作均位于视口内。
- 日期、时间、日期时间弹窗可视高 286px、内容高 366px，外层可滚到 80px，完成按钮到达视口内且能完成选择；各滚轮保留独立滚动。
- 多行标题底部面板内容区域自动收缩至约 143px，可滚到末项和底部按钮。
- 长下拉列表可滚到第 30 项；横屏下拉列表边界位于视口内。
- 嵌套检查另发现请假类型列表下沿曾到达 592px，超出 560px 视口。现按所选方向可用空间限制列表高度，复测可滚到并选中「远程工作」，关闭列表后仍能滚至保存按钮。
- 1280×800 下 8 类业务弹窗均位于视口内，保持原有桌面布局。

这里记录的是桌面浏览器的移动尺寸回归；不等同于 Android 真机触摸或系统键盘测试。
