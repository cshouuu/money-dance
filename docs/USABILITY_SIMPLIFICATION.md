# MoneyDance 易用性优化提案

日期：2026-09-14。阶段：需求方向稿，供产品讨论与后续原型使用；不是已实现功能。

目标：让用户先看到自己的时间价值，在需要处理特殊情况时仍能找到完整能力。优先减少首次决策、重复入口和跨页面理解成本。

## 1. 现状与判断

本稿依据当前源代码与 v0.4.0 说明梳理，尚未进行真人可用性测试。用户反馈是问题来源；以下具体原因是待验证的设计判断，不能当作已测出的用户行为。

| 源码证据 | 理解负担 | 优化方向 |
| --- | --- | --- |
| `navigation.ts` 有 10 个入口；`Shell.tsx` 在全部功能中平铺展示 | 用户先辨认模块，再判断在哪里做事 | 按任务归并入口，保留原功能与直达路径 |
| `Settings.tsx` 已有折叠分组，但工资组仍同时涉及发薪、折算、工作周 | 折叠减少页面长度，未减少决策和术语 | 基础设置与计算细则分层；工作周归入作息 |
| 月薪折算选项未按工资类型条件显示 | 时薪用户也看到不相关的选择 | 只显示对当前计薪方式有效的字段 |
| 出勤、排班、假期、工作旅程分别有配置入口 | 用户难以判断哪份设置正在起作用 | 日历统一承接当天变更，展示当前生效来源 |
| 今日同时呈现秒薪、进度、计薪时长、预计收入、概览、月战绩、心愿 | 核心金额与下一步操作被多组指标分散 | 首屏聚焦金额、状态和操作，统计下沉 |
| 意外收支与账本均有新增收支入口 | 用户需要理解两种录入的边界 | 统一“记一笔”，保留历史来源 |
| 默认薪资是 15000，设置预览无扣除时标为“税前” | 示例与个人数据、税前与到手口径可能混淆 | 明确首次设置状态及金额口径 |

旧 `INFORMATION_ARCHITECTURE.md` 仍描述早期五模块结构，与当前实现不一致。本稿以代码为准。

## 2. 产品主线与取舍

用户首先应能回答三个问题：“今天赚了多少？”“为什么是这个金额？”“今天有变化，在哪里改？”

保留实时工资、摸鱼、加班、账本、心愿的核心体验。排班、假期、工作经历、持有成本等能力继续存在，但无需所有用户预先学习。暂不新增简洁版/专业版切换、功能启用总开关或更多首页自定义项，避免把整理界面的工作交给用户。

本次不调整既有计薪公式、历史归属、法定日历规则和存量金额。需要新增工资口径记录、首次引导状态或影响范围预览的地方，作为明确的实现工作评估。

## 3. 建议的信息架构

默认一级入口统一为 **今日 / 账本 / 心愿 / 我的**。移动端已有自定义导航的用户保留原选择；新版默认仅用于新用户或主动恢复默认的用户。桌面端使用相同分组。

| 入口 | 默认内容 | 次级入口及保留能力 |
| --- | --- | --- |
| 今日 | 今日工资、当前状态、工作进度、摸鱼与加班快捷操作 | 调整今天、工作日历、计时记录、本月统计 |
| 账本 | 本月收入、支出、结余、记一笔 | 日/月/年切换、明细筛选、生活成本设置 |
| 心愿 | 目标价格、剩余工作时间、进度 | 已购好物、持有成本、起算日期等细节 |
| 我的 | 当前工资与作息摘要 | 工资与作息、工作经历、外观、导航偏好、更新、全部功能 |

“全部功能”保留为固定兜底目录，按工作、收支、心愿分组；不要求用户先自定义导航。原路由继续可达，Android 组件动作保持直达原操作。

“薪苦日历”主标题改为“工作日历”，品牌称呼可放副标题；“工作旅程”入口写成“工作经历”，说明“换工作、暂时休息、查看过去收入”。“物品”改为“已购好物”，放在心愿中；独立手工新增物品仍保留，不要求先建心愿。

## 4. 首次设置：三个短步骤

固定月薪用户是首版主要优化路径，时薪、弹性和轮班用户必须能从同一入口完成自己的分支。

1. **填工资。** 默认月薪，输入金额；通过一句明确的口径选择区分“到手金额”与“税前金额”。到手金额不再叠加工资扣除；税前金额可选填扣除项，也可暂时按税前估算。工资周期可改为年薪、日薪、时薪。
2. **选作息。** 提供“固定上下班 / 每天自己开始结束 / 按排班”三种场景。固定作息展示可直接修改的摘要，例如“周一至周五，09:00—18:00，午休 12:00—13:00 不计薪”；用户确认或修改。大小周只追问本周类型；排班进入对应配置。模板只是待确认值。
3. **看结果并开始。** 展示预计时薪、日薪与完整作息摘要，说明自动计薪还是需要每天点击开始，并提供返回修改入口。发薪日可稍后补充。

首次不要求填写月平均工作日、生活成本、工资历史、工作阶段名称、多段休息和外观偏好。复杂作息按分支处理，不把轮班用户硬套进固定作息。

未完成设置时，提供“设置我的工资”；若允许体验，所有金额明显标记为示例，不将示例数据自动写成用户账目。识别是否完成设置需要独立状态，不能以“工资是否等于 15000”判断老用户。

## 5. 设置改为摘要驱动

进入“我的”先看已保存配置：“月薪 ¥… · 周一至周五 · 09:00—18:00”，点击对应项再编辑。正在生效的高级配置也要出现在摘要中，例如“扣除 2 项”“正在使用排班”“扣生活成本后显示”，避免隐藏后找不到原因。

| 设置 | 默认呈现 | 何时展开 |
| --- | --- | --- |
| 工资金额、周期、金额口径 | 工资基础表单 | 始终可编辑 |
| 工作日、上下班、休息 | 作息摘要与基础编辑 | 与选择的作息类型匹配 |
| 月薪折算、月平均工作日 | “计算方式”次级入口及当前摘要 | 月薪/年薪相关；平均值仅在选择平均折算后显示 |
| 发薪日及遇休息日处理 | 可选“添加发薪日” | 填写日期后再展示调整方式；不猜测单位规则 |
| 工资扣除 | 工资口径下的可选明细 | 税前估算或已有扣除配置时 |
| 生活成本 | 账本中的可选设置，工资页提供关联入口 | 启用后说明是否改变首页金额；沿用存量模式 |
| 排班、多段休息、个人假期 | 相关作息或工作日历的入口 | 用户选轮班或主动编辑时 |
| 历史生效范围 | 保存变更时的范围摘要 | 主动修改范围时展开，不作为首次设置任务 |
| 外观、导航、更新 | 我的次级项目 | 与薪资表单分开 |

已有扣除的用户切换到手金额时，先解释并预览哪些扣除将停用，避免重复扣减；不能仅改显示文案。旧数据无法判断税前/到手时，显示“按已填工资估算”，不自动分类。

保存工资或作息时显示实际影响范围与前后预览。希望做到“从今天起修改、不改写过去”必须先核对现有历史配置能力；如果现有模型无法保证，应补齐版本化配置后再提供此承诺。历史重算作为明确的独立动作，仍保留手工账目和既有业务规则。

## 6. 今日页面与当天调整

首屏草图，数值使用占位符：

```text
今日                         工作日历
工作中 · 今天 09:00—18:00

今日预计已赚
¥ xxx.xx
按已填月薪估算 · 查看怎么算的
工作进度 ━━━━━━━━━━━  今日预计 ¥ xxx

[ 摸鱼 ] [ 加班 ]             调整今天
（有计时时显示进行状态和结束操作）

本月概览                        查看
心愿进度                        查看
```

固定作息用户无需每天打卡；弹性作息在未开始、工作中、暂停时分别突出开始、暂停、继续，结束操作同时可见。未配置、休息、请假、工作间隙和待结算各有对应说明。进行中的摸鱼、加班以及待结算不能折叠隐藏。

“查看怎么算的”先展示用户可核对的金额、时长和生效设置来源，再展开完整细节。区分工资估算、加班、工资扣除及生活成本；摸鱼金额说明为“工资中对应摸鱼时段的金额”，不暗示是额外收入。排班按班计薪、按自然日分摊等使用对应解释，不能统一套用时薪乘时长。

“调整今天”按意图提供：修改实际时间、请假/休息、今天临时上班、调整班次、修改当天工资。复用现有编辑器，完成后返回原页面。入口标注“仅修改这一天”；长期安排在同一处提供“修改常规作息”链接。跨日班次明确展示开班日期。

工作日历选中某天后，显示“今天按什么安排计算”和当前生效来源，例如手工调整、排班或常规作息。发生覆盖时解释具体结果，不要求用户记忆所有规则优先级；来源必须与实际计算逻辑一致。

## 7. 保留能力，减少重复选择

- **摸鱼与加班：** 今日提供快捷开始和结束，历史记录页保留补记、成就和预约。补记与预约放到次级操作，已有预约摘要和冲突状态保持可见。加班仍明确选择是否计薪，不自动猜倍率；可展示上次方式，但启动前显示本次将使用的金额规则。
- **意外收支：** 统一进入账本“记一笔”，基本字段为方向、金额、事项、日期。意外作为可选来源保留，旧记录继续可筛选。先统一入口与表单，再评估存储整合，避免重复记账。
- **心愿与好物：** 心愿购买后可关联已有好物流程，但保留不记账/关联既有支出的表达，避免一次购买重复产生支出。累计工作收入对应的进度不称作实际存款。
- **工作经历：** 换工作或暂时休息时使用；首次使用不必给工作阶段命名。阶段薪资、假期、排班继续保留，从当前工作摘要可达。
- **高级功能可发现性：** 次级入口使用“补记一次加班”“设置轮班”等任务名称，并在相关页面持续存在；不用纯图标或隐藏手势承担唯一入口。

## 8. 实施顺序

**第一批：降低现有界面的理解成本。** 调整设置分组和条件展示，将外观独立；增加当前配置摘要、金额口径说明、当天调整聚合入口；统一意外收支录入入口。以复用计算和编辑器为主。

**第二批：减少首次设置和首页负担。** 实现首次设置流程及数据状态、首页状态与操作层级、默认四入口及旧导航兼容。工资口径和保存范围涉及模型时，在此批补齐，不用文案掩盖限制。

**第三批：整合复杂场景。** 统一日历内的排班、假期、出勤入口与规则来源解释，整合工作经历及心愿/好物的跨页面路径。

每批均可独立验收。没有使用数据支持前，不删除摸鱼、加班或其他已存在能力，也不增加功能开关管理页。

## 9. 验收与验证

以下为建议目标，当前没有测量基线。使用同一组任务比较现版与原型；先进行 5—8 人形成性测试，覆盖固定月薪、弹性、轮班及已有复杂设置用户，小样本不推断整体人群比例。

| 任务 | 建议通过标准 |
| --- | --- |
| 固定月薪用户首次设置并看到自己的收入 | 无协助完成，目标中位时长 ≤ 60 秒；基础路径不出现月平均工作日等无关必填项 |
| 判断当前工资为什么如此计算 | 能说出工资口径、今日安排和是否扣生活成本；不必掌握计算术语 |
| 临时请半天假并核对结果 | 从今日找到入口并完成；能正确指出仅影响哪一天 |
| 时薪/轮班用户配置自己的工作 | 不需填写无关月薪参数；能找到对应配置并核对预览 |
| 新增支出或补记加班 | 不需比较重复模块；单次操作只产生一份对应记录 |
| 老用户找回排班、预约、好物及工作经历 | 从归属页面或全部功能可达；进行中状态持续可见 |
| 修改工资并检查历史 | 保存前能理解影响范围；实际变化与预览一致 |

实现验证使用固定业务日期和时间对照升级前后工资、账本及心愿结果，覆盖固定/弹性、跨日排班、请假和假期、工资扣除、生活成本两种模式、历史手工账目、已有自定义导航、Android 组件直达。界面优化本身不得改变金额；任何有意改变必须单独说明并验证。

方向评审重点：确认“今日、账本、心愿”为日常主线，以及固定月薪为首个优化路径。后续输出包含普通用户与轮班用户的原型、字段/状态规格及迁移方案；真实测试若显示日历或计时更高频，应据此调整默认入口。
