# 工作旅程 · Web / 移动端界面设计

设计日期：2026-09-09。可交互的独立设计原型，使用示例数据，不接入实际工资计算、账本、账户或线上部署。

## 打开设计

在项目根目录执行：

```powershell
python -m http.server 4179 --bind 127.0.0.1 --directory docs/design/work-journey
```

访问 http://127.0.0.1:4179/index.html，选择「双端对照」「Web 端」「移动端」。`app.html` 可以独立打开，自适应窗口宽度。

## 设计场景

| 场景 | 内容 |
| --- | --- |
| 在职 · 工作旅程 | 累计概览、当前工作、历史工作与休息时间线、阶段概览、薪资与时间快照 |
| 暂时休息 | 已停止原工作计薪、休息天数、最近工作总结、账本和物品入口、新工作入口 |
| 历史阶段 | 历史配置、每日出勤/工作时间/工时/薪资、分页、阶段总结、修改信息 |
| 首次使用 | 建立当前工作、补录过去的工作；支持缺失历史薪资 |
| 今日 · 休息态 | 替换在职计薪主卡，保留工作历史、日常收支、尾薪到账与新工作入口 |

## 主要交互

1. 点击时间线中的工作卡片查看详情。桌面端在右侧切换，移动端进入详情并提供返回入口。
2. 「结束这段工作」填写最后任职日，并处理一条示例未来预约；确认后展示阶段总结。
3. 阶段总结可以进入休息状态，也可开启新工作。
4. 当前工作未结束时，开启新工作会先进入阶段结束流程。
5. 新工作表单包含阶段名称、公司、岗位、日期、薪资与基础工作安排；支持必填和日期重叠校验。
6. 补录历史允许薪资留空，未知历史数据展示「待补充」，不生成虚假工资。
7. 历史日期修改先预览起止日期、任职天数和归属影响，再保存。实际薪资重算留待正式功能接入。
8. 「了解 WorkWorth」展示可选联动说明，未连接外部产品，不发送数据。
9. 移动端「全部」中展示工作旅程入口，保留现有底部五入口导航结构。

## 视觉与响应式

- 延续项目经典主题：画布 `#F5F2EA`，卡片 `#FCFAF5`，深绿 `#253A29`，强调色 `#526B49`，柔绿 `#DFE8B6`。
- 复用现有品牌标识；采用项目同类细线图标与数字等宽字体栈，无新增字体下载依赖。
- Web：232px 侧栏、280px 阶段时间线、右侧工作详情。桌面表单为居中对话框。
- ≤900px：沿用项目移动端导航断点，阶段列表与详情分层展示。表单从底部展开，正文滚动、操作区固定。
- 支持最窄 320px；平板采用有最大宽度的移动布局，避免并排详情过窄。
- 原生 dialog 支持键盘焦点约束、Escape 关闭；按钮有焦点状态，尊重减少动画偏好。

## 原型边界

- 页面内明确标识示例数据。修改只保存在当前页面内存，刷新恢复。
- 新工作创建后的每日记录为空，不借用其他阶段的明细。
- 示例标准日薪采用 20 个工作日的假设；正式功能必须沿用 MoneyDance 当前的计算规则，不使用原型算法。
- 固定/弹性、跨日、多段休息、扣减项与调休日历应复用现有薪资设置组件。本稿只展示基本字段与入口关系。
- 其他现有模块的导航给出原型提示，不复制其完整功能。
- 日期调整展示界面与范围变化，不模拟真实记录迁移或工资重算。
- WorkWorth 只作产品入口及导入意图示意；累计收入不等同于可动用余额。
