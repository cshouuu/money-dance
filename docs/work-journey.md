# 工作旅程

路由：`/journey`。桌面侧栏位于「工作记录」；移动端位于「全部」。沿用现有薪资、出勤、计时和账本计算，不依赖服务端。

## 使用流程

- 首次建立当前工作时，带入已有薪资与完整作息。日期之前的自动工资不再属于该阶段，请确认实际入职日。
- 结束工作或修改阶段时，最后任职日可以选择未来日期，但不能早于入职日，也不能与其他工作重叠。保存前预览日期和已有记录的归属影响。最后任职日含当天；最后一班跨夜工作继续计至班次结束。
- 未结算的工作、摸鱼和加班计时需要先完成。落在工作日期之外的预约经勾选确认后取消，已完成记录保留。
- 休息期不生成自动工资，不启动新的工作计时或预约；今日页展示休息状态。账本、物品与历史明细继续可用。
- 新工作独立保存薪资和作息，不覆盖已结束阶段。最后任职日为今天时，新工作默认从次日开始。
- 补录历史允许不填写薪资和工时，显示「待补充」，不以当前工资推算。首次直接补录会保留原薪资设置对应的当前工作，并提示起始日期。
- 历史阶段可查看按日工资、出勤、工作时间与工时；日期与薪资修改需要先预览影响。每日自动工资仍受原薪资历史生效日限制。
- 账本中的手动收入可选择关联工作，供未入账的补发、奖金等使用；保留实际到账日期，阶段页单列展示，避免与自动工资混淆。

## 数据与边界

`SalaryProfile.workJourney` 是可选的版本化结构，包含 `revision` 和工作阶段数组。尚未启用的用户保持原有单工作计算。阶段起止使用设备本地日期，结束日包含当天，阶段日期不得重叠。

各阶段保存不含旅程本身的完整薪资快照。未到期的计划离职阶段仍属于当前工作；薪资设置和预览修改当前阶段，休息期则选择最近的未来工作，其他阶段的规则保持独立。统一入口按业务日期选择所属阶段的工资、工作方式、休息、扣减与月薪换算规则。实际月历换算仍采用整月计薪天数，避免将整月工资分摊到几天任职期。新阶段不继承上一段的工资扣减项；个人生活费历史继续保留。

阶段日期改变时，出勤和工作记录保留原日期。范围外不再自动计薪；手动收支不被删除。未知历史工资不生成自动工资或估算工时。

工作快照与当前薪资保存在同一个本地存储项中。阶段保存检查打开表单时的配置版本，并与预约控制器共享 Web Lock。涉及预约取消的多项写入复用可回滚存储事务；失败保留表单并提示重试。浏览器存储本身仍受设备空间与清理策略影响，与项目原有 local-first 模式一致。

WorkWorth 当前仅为可选产品说明入口，未连接外部服务，也不会发送薪资或工作数据。累计工资不是可动用存款。

## 主题与双端

新页面、时间线、弹窗、输入框与休息首页使用现有语义颜色变量。主卡使用 `--theme-hero-*`，按钮使用 `--dark` / `--on-dark`，不会把浅色主题的主卡文字固定为白色。

桌面显示时间线与阶段详情两栏；900px 以下分开显示列表和详情。移动端表单从底部展开，正文可滚动、操作区固定，并复用模态框滚动锁。原生 dialog 提供焦点约束与 Escape 关闭。表单统一复用 beUI：文本与金额使用 Input，日期与时间通过 Input 接入 DateTimeField 滚轮选择器，下拉选择使用 SelectField，勾选项使用 Checkbox；操作按钮、详情标签页、高级规则分别使用 Button、Tabs 和 BouncyAccordion。移动端日期独占一行，休息时段纵向排列，避免 320px 窄屏截断。

DateTimeField 和 SelectField 在原生 dialog 内使用时，将浮层挂到最近的 dialog，确保浮层位于可交互的模态顶层；其他页面继续挂到 body。Escape 优先关闭选择器，不连带关闭工作表单。业务页面样式限定到自己的标题和操作区，避免覆盖嵌套选择器。导航链接、表格和模态容器保留语义 HTML；账本新增的「关联工作」字段也使用 SelectField。

### 未来离职日期

- 未来结束日期显示「将于 YYYY.MM.DD 结束」，最后任职日当天显示「今日最后任职」，次日才显示「已结束 / 已归档」。累计任职天数只统计已经历日期，预览单独展示预计任职天数。
- 到期前保持工作首页及正常计薪；最后任职日结束后进入休息模式，跨夜末班保留到结束。已有按业务日期判断的首页不需要额外预约任务。
- 到期前仍可修改最后任职日与薪资；自动工资和未来预约使用更新后的日期范围，范围外预约沿用确认取消机制。
- 新增 6 项测试覆盖未来日期校验、状态与已历天数、普通班和跨夜末班切换、当前和下一段薪资隔离、延期后保留范围内预约。
- 浏览器使用独立 localhost 开发来源验证未来日期选择、保存、修改及首页状态，避免改动 127.0.0.1 的用户记录。
