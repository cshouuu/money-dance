# 寒暑假与长假安排

入口位于「薪苦日历 → 假期安排」及「工作旅程 → 阶段概览 → 阶段假期」。复用 beUI 的底部面板、选择器、日期选择器和按钮；首页只替换已有状态及倒计时，不新增卡片。

- 首尾日期均包含当天，支持寒假、暑假、自定义，单段不超过 366 天。同一工作阶段不允许日期重叠。
- 支持工资照常、0–100% 比例、指定假期月薪、不计薪。复制保留原日期和计薪规则，修改日期后保存。
- 保存或删除前预览受影响月份的预计收入、历史重算提示和保留的出勤 / 计时天数。返回、关闭均不会写入草稿；存储失败保留编辑状态，过期页面不能覆盖新设置。
- 假期保存在个人薪资设置的独立 `vacations` 数组，不批量生成或删除单日出勤。开启工作旅程后以 `stageId` 关联阶段；原有假期迁入相交的工作阶段。
- 更改任职范围后，保留假期原日期，只在所属阶段实际任职范围内生效；不自动延续到下一份工作。阶段摘要、阶段假期列表及每日明细均显示关联假期。

## 工时与计薪

单日手工出勤优先于假期安排，其次是国家节假日与补班、固定工作周或大小周。实际保存的计时继续保留。默认值班只改变工时；单日明确指定的计薪金额或倍率优先，额外补贴可另记加班。

月薪 / 年薪在涉及假期的月份使用原计薪日份额分摊（包括原来选择月平均折算的用户），不把放假天数从分母中删除。假期周末不会额外获得一份日薪。比例作用于该日期原有的工资份额；指定假期月薪为替代月薪标准，沿用工资扣除设置，再按原计薪日分摊，部分月只替换假期覆盖部分。日薪 / 时薪照常模式沿用原标准，指定假期月薪时使用原日历计薪日分摊。

假期工资按日记入自动工资，不产生正常工作工时；日历手工调整与账本工资调整沿用原优先级。无计划工时的月份显示「本月无计划上班」；没有工时的综合时薪显示「暂无数据」。个人长假不改变发薪日采用的常规日历。

假期前提示距离假期的天数，假期中显示含当天的剩余天数，并从结束日期后查找实际恢复上班日期（跳过原周末、后续假期等）。已设置离职日期时，不推算任职范围外的恢复日期。

## 验证

`vacations.test.ts` 覆盖整月四种计薪、部分月分摊、值班及单日工资覆盖、实际计时保留、国家补班与大小周、跨月年薪扣除、恢复日期、发薪日、工作阶段关联及裁剪、历史预览、重叠日期、存储失败和过期编辑。

## 联动适配

- 非假期月份保持原月平均 / 实际日历折算方式。假期被任职日期完全裁掉后，也不改变该月折算方式。
- 弹性值班少于目标工时，沿用假期或单日出勤工资，不再询问是否补足全天工资；超出目标工时仍可独立结算加班，面板展示实际基本工资。首页预计金额同步使用假期工资。
- 首页及工作旅程的未来假期提示使用实际生效日期。返岗日期识别已记录的周末值班，同时尊重手工休息调整。
- 摸鱼及心愿进度继续按工作时段和薪资单价折算；假期休息不增加工时或心愿进度，临时值班保留实际工时。折算金额不是额外工资，独立加班仍按用户设置计薪。
- 安卓快照新增可选 `paidWorkTimeline`，将实际工时与 `workTimeline` 的每日工资分开。带薪假日不产生摸鱼收益；固定工资值班仍能累计摸鱼时间。原生端兼容缺少新字段的旧快照；升级 APK 后使用新逻辑。

联动回归还覆盖非假期月份、裁剪后的未来假期、周末值班返岗、预约摸鱼 / 加班、心愿与桌面组件的一致性。原生 JVM 用例见 `apps/web/native/android/tests/README.md`；APK 的安装与真机显示仍需要发布前验收。
