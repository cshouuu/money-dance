# SalaryFlow / 薪流 — 产品需求文档 PRD

> 版本：MVP v0.1  
> 产品定位：把「工资、工作时间、消费、持有成本」连接起来的个人时间价值仪表盘。

## 1. 背景与机会

传统工资计算器只解决“工资换算”这一瞬时需求，使用频率低、缺乏情绪价值。SalaryFlow 将工资转化为实时增长的数字，并把消费价格重新表达为“需要工作多久”，让用户在工作日内持续获得反馈。

产品同时满足四类需求：

1. **实用**：月薪/年薪/日薪/时薪换算成日、时、分、秒薪资。
2. **即时反馈**：展示“今天到此刻已经赚了多少钱”，数字持续变化。
3. **娱乐与传播**：摸鱼计时并显示“这段摸鱼老板付了多少钱”。
4. **消费反思**：把商品价格换成工作时间，并计算已购物品随时间下降的持有成本。

## 2. 产品目标

### 2.1 MVP 目标

- 用户在 60 秒内完成薪资设置并看到实时收入。
- 四个核心功能都可在不注册的情况下完整使用。
- 页面刷新、锁屏、切后台后，摸鱼计时与动态金额仍准确。
- 所有薪资隐私数据默认仅保存在本地浏览器。
- 桌面端与移动端都具备完整可用性。

### 2.2 非目标

MVP 不处理：

- 个税、社保、公积金、不同国家税率。
- 加班费法定倍率。
- 法定节假日自动识别。
- 多币种实时汇率。
- 多设备账号同步。
- 公司考勤系统集成。
- 实际“使用时长”追踪；MVP 的物品模块先统计“持有成本/小时”。

## 3. 核心用户

### A. 上班族
想知道自己此刻实际赚了多少、离下班还有多久。

### B. 工具/效率爱好者
喜欢可量化的数据、实时仪表盘、计时器。

### C. 内容分享用户
愿意分享“我摸鱼赚了 ¥XX”“iPhone = 我工作 XX 天”等有趣结果。

## 4. 核心用户旅程

### 首次访问

1. 打开网站。
2. 进入“薪资设置”。
3. 输入工资周期、金额、上下班时间、午休规则。
4. 即时预览日薪/时薪/分钟薪资/秒薪。
5. 保存后进入“今日”。
6. 看到当前已赚金额和工作进度。

### 日常访问

- 查看今日实时收入。
- 开始/结束摸鱼。
- 输入商品价格换算工作时间。
- 查看已购物品当前每小时持有成本。

## 5. 功能需求

## 5.1 实时薪资

### 输入

- 工资金额，>= 0。
- 工资周期：月薪 / 年薪 / 日薪 / 时薪。
- 月平均工作日，默认 21.75。
- 每周工作日，默认 5（MVP 仅用于展示/后续扩展）。
- 上班时间。
- 下班时间。
- 午休开始时间。
- 午休结束时间。
- 午休是否计薪。

### 输出

- 日薪。
- 时薪。
- 分钟薪资。
- 秒薪。
- 今日已计薪时长。
- 今日已赚金额。
- 今日工作进度。
- 今日预计收入。

### 动态规则

- 前端每 100~250ms 重算展示金额，制造平滑“涨工资”效果。
- 不每秒写数据库或 localStorage。
- 真实值始终由 `当前时间 - 工作开始时间 - 未计薪休息交集` 计算。
- 下班后金额封顶，不继续增长。
- 上班前为 0。

## 5.2 商品价格 → 工作时间

### 用户操作

1. 输入名称。
2. 输入价格。
3. 即时显示需要工作多久。
4. 可保存记录。
5. 可删除历史记录。

### 输出

- 所需工作秒数。
- 人类可读时间，例如“2天6小时12分钟”。
- 折算为“工作日”数量。

### 计算

`所需工作秒数 = 商品价格 / 秒薪`

工作日换算必须使用用户实际的每日计薪秒数，而不是固定 8 小时。

## 5.3 摸鱼计时

### 开始

保存 `startTime = ISO 时间戳`。

### 进行中

- 每 250ms 根据系统当前时间重算持续时间。
- 显示 HH:mm:ss。
- 显示当前已赚金额。
- 浏览器刷新后从 localStorage 恢复 startTime。

### 结束

保存：

- startTime
- endTime
- durationSeconds
- earnedAmount

### 历史统计

MVP 提供：

- 本次摸鱼收入。
- 历史摸鱼总时长。
- 历史摸鱼总收入。
- 最近 20 次记录。

后续可加：今日 / 本周 / 本月维度与排行榜式分享卡片。

## 5.4 物品持有成本

### 定义

MVP 指标名称应使用“持有成本”，而不是“实际使用成本”。

`当前持有成本/小时 = 购买价格 / 从购买时间到当前时间的小时数`

### 输入

- 物品名称。
- 价格。
- 购买日期。
- 分类。

### 输出

- 当前持有成本 / 小时。
- 已拥有天数。
- 价格。

### 动态规则

- UI 每分钟刷新一次即可。
- 真实指标连续下降；产品文案可描述为“每小时自动下降”。
- 购买日期不可晚于当前时间。

## 5.5 薪资设置

保存后影响：

- 首页实时收入。
- 首页发薪倒计时；发薪日支持每月 1–31 日，小月自动按月末计算。
- 商品换算。
- 新产生的摸鱼金额。

历史摸鱼记录保存结束时的 earnedAmount，不因用户后来修改薪资而被追溯修改。

## 6. 数据策略

### MVP：Local-first

数据默认保存在浏览器 localStorage：

- SalaryProfile
- WishItem[]
- SlackingSession[]
- ActiveSlacking startTime
- OwnedItem[]

优点：

- 无注册门槛。
- 薪资隐私更友好。
- 无数据库即可上线。
- 离线/弱网仍能使用主要功能。

### 后续：Cloud Sync

增加账号系统后，服务端采用用户 ID 隔离数据。可接 Neon / Supabase / PostgreSQL，但不改变核心计算包。

## 7. 成功指标

MVP 建议埋点（后续接分析工具）：

- onboarding_completed
- dashboard_viewed
- converter_item_created
- slacking_started
- slacking_finished
- owned_item_created
- share_card_generated（V2）

核心指标：

- 首次设置完成率。
- 次日回访率。
- 每用户每周摸鱼计时次数。
- 每用户换算商品数。
- 分享卡片生成率（V2）。

## 8. 体验原则

- 首页只突出一个最大数字：今天已赚多少钱。
- 使用“时间价值”而不是财务软件的视觉语言。
- 避免过度游戏化导致廉价感。
- 金额动态但布局不抖动，金额使用等宽数字字体。
- 手机端底部五导航，桌面端左侧导航。
- 用户不登录也必须拥有完整 MVP 体验。

## 9. V2 候选

按价值排序：

1. 分享卡片：摸鱼收益、商品 = 工作时间、持有成本。
2. 实际使用计时：物品真实使用成本/小时。
3. 本周/本月数据报告。
4. 多币种与汇率。
5. 工作日历与节假日。
6. 账号/云同步。
7. PWA/桌面小组件。
