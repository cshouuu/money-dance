# MoneyDance — 计算规则与异常场景

## 1. 时间统一原则

所有计时逻辑都遵循：

- 数据层保存绝对时间戳（ISO 8601）。
- UI 刷新频率不代表真实计时精度。
- 页面恢复后用 `now - startTime` 重算，而不是恢复一个自增计数器。
- 金额展示可高频更新，但不高频持久化。
- 固定跨日班次以班次开始日作为业务日期，使用该日的出勤和节假日规则；弹性工作和加班收入同样归属各自开始日。
- 日期型工资、生活成本和工资覆盖除 `occurredAt` 外还保存设备本地业务日期。账本筛选和排序优先使用该日期，之后切换时区不会把账目移动到相邻日期；旧工资覆盖可从被替换的工资 ID 恢复业务日期。

## 2. 每日计薪时长

设：

- `S` = 上班时间。
- `E` = 下班时间。
- `B1` = 午休开始。
- `B2` = 午休结束。

### 普通班次

`shiftSeconds = E - S`

### 跨天班次

若 `E < S`：

`shiftSeconds = 24h - S + E`

### 午休不计薪

只减去午休与班次的真实交集：

`paidSeconds = shiftSeconds - overlap(shift, break)`

这样可防止用户把午休填到工作区间外导致负时长。

## 3. 工资周期换算

### 月薪

`dailySalary = monthlySalary / monthlyWorkDays`

### 年薪

`dailySalary = annualSalary / 12 / monthlyWorkDays`

### 日薪

`dailySalary = inputSalary`

### 时薪

`dailySalary = hourlySalary × paidSecondsPerDay / 3600`

随后统一：

`secondSalary = dailySalary / paidSecondsPerDay`

`minuteSalary = secondSalary × 60`

`hourlySalary = secondSalary × 3600`

### 生活成本

开启生活成本后提供两种互斥模式：

- **从工资速度扣除**：沿用原规则，将月生活成本按月平均工作日摊成每日成本，再从各工资类型换算出的日薪中扣除（最低为 0），据此计算时薪、分钟薪资和秒薪。
- **每日记入账本**：工资速度继续使用税后工资原值，月生活成本按所在月的自然日数拆成每日支出，包括周末和节假日。

每日账本模式从用户首次明确选择该模式的设备本地日期生效，不与薪资历史生效日期共用。模式和月金额按业务日期保存配置事件：账本为每个历史工资日解析当日生效的生活成本口径，后续修改不会把过去的净工资重算成毛工资，反之亦然；关闭生活成本或切回工资扣除模式后，已经生成的历史每日支出仍保留，修改当天起停止生成。

工资覆盖同时记录其金额是否已经扣除生活成本。切换到每日账本模式后，已扣生活成本的覆盖不会在同一天再次生成固定生活成本支出；按毛工资填写的覆盖仍正常生成该日支出。旧覆盖会根据其业务日期和切换前配置安全推断，避免历史双扣。

每日金额以“分”为最小单位分配余数，从每月月初依次多分 1 分，保证整月配置未变化时所有日支出之和严格等于设置的月金额；不生成未来日期的支出。

## 4. 今日已赚金额

### 固定作息

`workedPaidSeconds = 已经过的班次秒数 - 已经过的未计薪休息秒数`

必须 clamp：

`0 <= workedPaidSeconds <= paidSecondsPerDay`

`earnedToday = workedPaidSeconds × secondSalary`

### 午休期间

若午休不计薪，收入数字暂停增长；午休结束后继续。

### 下班后

`workedPaidSeconds = paidSecondsPerDay`，收入封顶为 dailySalary。

### 上班前

`workedPaidSeconds = 0`。

### 弹性作息

弹性作息只累计每一段“开始工作—暂停 / 结束工作”的实际秒数：

`flexibleWorkedSeconds = sum(sessionEnd - sessionStart)`

工作过程中正常工资的实时展示仍封顶到目标工时：

`flexibleLiveEarned = min(flexibleWorkedSeconds, targetSeconds) × currentSecondSalary`

- 暂停期间不计薪；午休不会自动从弹性时长中扣除，用户可通过暂停排除实际休息时间。
- 未结束的工作段以当前时间作为临时结束时间；真实工作时长不封顶。
- 开始弹性工作时可以选填预计结束时间。达到该时刻后不再继续累计，应用下次恢复时将冻结记录并打开结算流程；Android 小组件的工资时间片也在该秒停止。
- 未达到目标工时时，如果当天没有薪苦日历工资覆盖，所有工资类型均由用户选择按实际时长、按完整日薪，或前往薪苦日历设置请假 / 特殊出勤；已有覆盖时直接以薪苦日历结果结算。
- 刚好达到目标工时后自动按完整日薪结算。
- 超过目标工时时，正常工时按完整日薪结算；若薪苦日历已覆盖当天工资，则正常部分以覆盖金额为准。超出的真实工作片段无论是否计薪，都会生成独立加班记录并计入加班成就；输入工资倍率或设置固定金额时另生成账本收入，无加班费时不生成收入账目。暂停时间不会混入加班时长。
- 选择全天工资只改变当日收入金额，实际工作时长仍保留真实记录。
- 旧记录没有结算方式时继续按实际时长计算，避免历史短工时被自动放大为全天工资。
- 薪苦日历中的请假、放假或正常出勤自定义工资优先于弹性工作结算方式。

### 薪苦日历工资覆盖

正常出勤未设置计薪方式时，继续使用固定或弹性作息的自动计薪结果。用户明确设置后，按整天工资覆盖：

`normalAttendanceMultiplierPay = dailySalary × attendanceMultiplier`

`normalAttendanceFixedPay = attendanceFixedAmount`

- 倍率和固定金额只覆盖当天工资金额，不改变真实工作时长、工作状态或弹性工作记录。
- 正常出勤自定义工资、请假和放假均优先于当天自动工资及已有的手工工资调整。
- 删除该日出勤调整后，恢复自动计薪；此前被覆盖的手工工资调整重新生效。
- 旧的正常出勤记录没有计薪方式时继续按默认工资计算，不需要数据迁移。

半天请假保留另一半正常工资：

`halfDayUnpaid = 0.5 × dailySalary`

`halfDayMultiplier = 0.5 × dailySalary + 0.5 × dailySalary × leaveMultiplier`

`halfDayFixed = 0.5 × dailySalary + fixedLeaveAmount`

其中固定金额只代表请假的半天，不是整日总工资。半天请假时，首页的目标工时也同步变为正常目标的一半。

### 中国大陆节假日与调休补班

自动判断优先级固定为：

`手工出勤或当日已保存的工作记录 > 已公布的官方节假日日历 > 固定工作周 / 大小周`

- 当前内置 2025、2026 年国务院公布安排；默认从升级后首次加载该功能的设备本地日期生效，不回算此前历史。关闭后重新开启时，从重新开启当天重新生效。
- 官方休息日不自动生成 2 倍或 3 倍工资，调休补班日只按普通工作日处理。
- 月薪 / 年薪用户仅法定假日本身保留 1 倍正常日薪；长假中的调休休息日不再重复生成工资。
- 日薪 / 时薪用户在官方休息日默认不计工资，仍可通过薪苦日历手工覆盖。
- 未内置年份自动退回用户配置的工作周规则，避免把未知安排误判为休息或补班。

## 5. 商品换算

`requiredSeconds = price / secondSalary`

异常：

- price < 0：拒绝。
- price = 0：0 秒。
- secondSalary = 0：结果为 Infinity，UI 显示 `∞`，不崩溃。

工作日：

`requiredWorkDays = requiredSeconds / paidSecondsPerDay`

注意：不能除固定 8 小时。

## 6. 摸鱼计时

### 进行中

`elapsedSeconds = max(0, now - startTime)`

`earned = elapsedSeconds × currentSecondSalary`

### 结束时

冻结：

`earnedAmount = (endTime - startTime) × 当次结束时使用的 secondSalary`

MVP 不因用户未来修改薪资而重算历史记录。

开始计时可以填写已经过去的实际开始时间；若整段都已结束，也可以一次性补记开始和结束时间。该能力是轻量补时，不创建 Android 闹钟、后台任务或未来定时启动：用户只能记录当前时刻或已经发生的时段。补记不得晚于当前时间，也不得与已有或进行中的同类记录重叠。摸鱼与加班都按补记时的当前工资速度计算，不追溯历史薪资快照。

加班补记继续支持无加班费、自定义工资倍率和固定金额。工资倍率必须由用户输入大于 0 的数字；跨日记录的收入归属开始日期，展示统计可以按本地自然日拆分时长。

### 设备时间被修改

浏览器无法可靠防止用户手工修改系统时钟。MVP：

- 若 `end < start`，duration clamp 到 0。
- 后续云同步版可用服务端时间进行异常检测。

## 7. 物品持有成本

`elapsedHours = (now - purchaseDate) / 3600000`

`costPerHour = price / elapsedHours`

异常：

- purchaseDate > now：拒绝新增。
- elapsedHours <= 0：返回 Infinity，UI 显示 `—`。
- price = 0：成本为 0。

## 8. 输入校验表

| 场景 | 规则 | UI 行为 |
|---|---|---|
| 工资为空 | 无法计算 | 禁止保存或显示校验 |
| 工资 < 0 | 非法 | 拒绝 |
| 工资 = 0 | 允许 | 秒薪 0，商品换算 ∞ |
| 月工作日 <= 0 | 非法 | 拒绝 |
| 月工作日 > 31 | UI 限制 | 不建议允许 |
| 上下班相同 | 0 小时班次 | 拒绝保存 |
| 下班 < 上班 | 视为跨天班次 | 正常计算 |
| 午休在班次外 | 不扣除 | 正常计算 |
| 午休覆盖整个班次 | paidSeconds <= 0 | 拒绝保存 |
| 商品价格 < 0 | 非法 | 拒绝 |
| 商品价格 = 0 | 允许 | 0 秒 |
| 购买日期未来 | 非法 | 拒绝 |
| 摸鱼 / 加班补记时间在未来 | 非法 | 拒绝保存并保留表单 |
| 摸鱼 / 加班到点自动开始 | 不支持 | 使用轻量补时记录已经发生的遗漏时段 |
| 摸鱼 / 加班补记与已有记录重叠 | 非法 | 拒绝保存并指出冲突 |
| 弹性工作超过目标工时 | 需要结算 | 选择超出部分不计薪、倍率或固定金额 |
| 摸鱼刷新页面 | 恢复 | startTime 继续计时 |
| 多开标签页 | MVP 不做锁 | 可能同时操作；V2 用 BroadcastChannel |
| localStorage 被清空 | 数据丢失 | MVP 可接受；V2 云同步 |
| 时区变化 | ISO 时间戳仍有效 | 日统计日期可能按新本地时区归类 |
| 浏览器休眠 | 不依赖 interval 累加 | 恢复后自动校准 |

## 9. 精度策略

内部全部使用 JavaScript Number 的秒级浮点数；展示层：

- 总金额：2 位小数。
- 时薪：2 位。
- 分钟薪资：3 位。
- 秒薪：5 位。
- 实时金额可以 2 位显示并 100ms 更新。
- 不将格式化后的字符串参与后续计算。

如未来涉及账务结算，再改用 decimal 库；MVP 属于展示型工具，不承担金融结算责任。
