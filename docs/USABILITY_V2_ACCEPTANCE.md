# 出勤设置易用性优化 V2 · 测试说明

分支：`codex/feature-usability`。未合并 main；首页与导航结构沿用正式版。测试项目为 `money-dance-usability`，正式站点、正式 Android 发布流程与正式应用 ID 均未改动。

## 这版解决的问题

- 同一工作的工资、扣除项和作息按生效日期保存。月初或月中调薪不再覆盖之前月份；已保存的后续规则继续生效。历史纠错需明确选择日期并确认影响。
- 月薪默认按实际计薪日分摊。旧用户的月平均天数算法保留，界面明确它是固定日单价估算，整月合计可能与月薪不同。工资与作息保存位置展示日期和生效月份的收入预估。
- 工作周移至上班安排；大小周用“周一至六 / 周一至五”表达，并显示本周与下周。启用排班时，普通作息收在明确的备用入口中。
- 新排班模板沿用原上下班时间与不计薪休息；手动排班可同时安排首日，只有班次模板时不能无提示地启用空排班。保存前解释月份工时、时薪和心愿估算的关系。
- 请假先选择全天/半天，再选择不计薪、工资照常或另设金额；常规带薪假无需填倍率。展示当天基本工资预估；遇到排班最终工资或账本手工工资时，只展示当前冲突及处理方式。
- 工作经历可删除。删除移除该经历的规则及关联排班、假期，取消对应未执行预约，保留原始出勤/计时/手工收支，解除手工账目关联。最后一段删除后不会恢复旧的自动计薪。提供撤销；相关数据有后续修改时拒绝覆盖新数据，已过期预约不重新启动。
- 摸鱼与普通加班记录可直接修改并预览金额，保留原记录 ID，检查时间重叠、并发修改及存储失败。加班同步更新关联账目；同日起止时间修正沿用该记录的原单价。由弹性工作结算产生的分段加班保留原管理方式。
- 固定月薪的摸鱼工资里程碑不再因为休息日或空排班而全部归零。已结算计时金额、永久成就逻辑保留；修正时长仅增加尚未记入的成就时长，不重复累加。
- 通过此设置流程调整个人生活成本时，也保留此前的规则；个人生活成本从保存当天生效。

## 计算边界

1. 在无扣除、无特殊调整、整月按约定出勤时，实际日历分摊的整月基本工资等于月薪。月中调薪按各日期的工资和整月计薪日分摊。
2. 本月工作周或排班工时变化会更新本月的时间折算，可能改变本月参考日薪、时薪及按工时估算的心愿进度。界面明确说明这一点；不通过冻结错误分母保住表面数字。
3. 排班月薪仍按自然日分摊基本工资，按班/按小时计薪仍沿用各自规则。缺少计划工时不能推导可靠参考时薪，但月薪与已结算收益仍然存在。
4. 选择早于现有自动记薪起点的生效日期时，自动记薪起点同步提前；普通调薪保持原起点。
5. 编辑工作经历里的原始薪资属于整段历史纠错，会替换该段已保存的工资/作息版本。普通调薪使用设置页的生效日期。

## 验证与建议验收

自动化覆盖：无工作旅程和有工作旅程的历史工资保护、月中调薪、月中作息变动、未来调薪、历史纠错保留后续版本、首次建立旅程的兼容、删除/撤销/失败回滚/并发修改、过期预约、空排班里程碑。原有跨日班次、半天假、长假值班、工资扣除、组件与永久成就测试继续运行。

移动端实际页面操作覆盖：连续保存两次调薪、两周轮换、删除最后一段经历并撤销、摸鱼时间纠错、加班原单价与关联账目、半天带薪假、手动排班首日设置。截图和浏览器结果保存在本地 `output/v2-*.png`、`output/usability-v2-browser-results.json`。

建议依次验收：月薪 4000 → 下月 5000，确认旧月不变；半天无薪假与带薪假；固定作息转手动排班；补录错误经历后删除/撤销；忘记停表后修改结束时间。真实复杂排班可继续用测试应用验证，验收通过前不发布正式版本。
